myAnbari API (v1)

A guide for the developer of a shop's own website or app. With this API your website can:

  • show what is in stock and what is sold out,
  • add new products and edit them,
  • record sales (online orders) and incoming stock,
  • read recent sales and stock changes, each with where it came from.

Every sale or stock change your website sends shows up in the shop's app with a small «سایت» (website) label, so the shop always knows which sales came from the website, which were typed by hand, by an employee, by voice, by barcode scan, or by ChatGPT / Claude.

Plan: the API is part of the «پلاس» (Plus) plan only. On the free plan and on «استاندارد» (Standard) every request answers 402 api_plus_only (see Errors). Keys are never deleted by this: when the shop moves to Plus, the same keys work again.

  • For ChatGPT, Claude or another MCP app, use the AI connector instead (no code needed): see docs/MCP.md.
  • Base URL: https://<your-anbari-address>/api/v1 (the same address you open Anbari with).
  • Human-readable copy of this page: /api/docs. Plain Markdown: /api/docs.md.
  • Everything is JSON (UTF-8) unless a file is requested.

Getting a key

In the app: Data → Connections → API keys («اتصال به اپ‌های دیگر»). Only the shop owner can make keys, and only on the Plus plan; on other plans the screen shows an upgrade card instead.

  • Give the key a name (for example "menu website") and choose what it may do (scopes, below).
  • The key is shown once. Copy it then. Anbari stores only a fingerprint of it, so a lost key cannot be shown again; make a new one.
  • Keys expire after 30, 90, 180 or 365 days (your choice, 90 by default). Revoke a key any time; it stops working at once.
  • Each request is recorded against the key (last used time, and an audit entry for every change).

Sending the key

Send the key in a header on every request:

Authorization: Bearer <key>

or

X-Api-Key: <key>

Never put a key in a URL, and keep keys on your server. A key that can sell, receive, change prices or import must never be placed in web page code: browsers are refused for those requests. Read-only requests (GET) are allowed from any website (CORS *, no cookies), but anyone who can see a key in page code can read your stock with it, so prefer calling from your server even for reading.

Scopes

ScopeAllows
inventory:readRead products, stock, availability, selling prices, categories and photos; download CSV/Excel.
inventory:sellRecord sales (POST /sales).
inventory:receiveRecord incoming stock (POST /receipts).
pricesChange selling and purchase prices; also shows purchase costs (costPrice, avgCost) in product data.
importSend a stock-count file (Excel, CSV or JSON rows) that sets each product's stock to the counted amount.
catalogCreate and edit products (POST /products, PATCH /products/{id}). Setting a purchase price (costPrice) also needs prices.

For a normal shop website: inventory:read + inventory:sell (+ catalog if the website adds products).

A request without the needed scope gets 403 insufficient_scope with the missing scope in required.

GET /products (also GET /inventory)

Query options: q (search in name, brand or exact barcode), category, available=true|false, limit (1–500, default 100), cursor (the nextCursor of the previous page).

{
  "products": [
    {
      "id": "3f1c…", "name": "Milk", "brand": null, "category": "Dairy", "unit": "l", "kind": "simple",
      "barcode": "626…", "size": null, "color": null, "description": "",
      "stock": 7, "available": true, "price": 30000,
      "photo": "/api/v1/products/3f1c…/photo", "version": 4, "updatedAt": "2026-09-27T08:10:00.000Z"
    },
    {
      "id": "9a0d…", "name": "Latte", "kind": "made", "unit": "piece",
      "stock": 28, "available": true, "price": 90000, "…": "…"
    }
  ],
  "nextCursor": null,
  "revision": 42
}
  • stock for a normal product is the amount on hand. For a made product (it has a recipe) it is how many can be made from the ingredients on hand; null means no recipe, so it is always available.
  • available is true when stock is above zero (or null). A menu should hide or grey out items with available: false.
  • price is the selling price (toman) or null. costPrice and avgCost appear only for keys with the prices scope.
  • revision goes up whenever anything in the shop changes. Keep the last one and ask GET /changes?since=<revision> for only what changed.

GET /products/lookup

Find one product by its code or name. Send exactly one of barcode, sku or name (exact name).

GET /api/v1/products/lookup?sku=CK-1

Answer: {"product": {...}}. Several products with the same code: the newest is returned and moreWithSameCode: true is added. No match: 404 product_not_found.

sku and barcode are the same field in the app (the product's code). A website can store its own SKU there.

GET /stock

Query options: status=all|available|out|low (default all), limit (1–500, default 100), cursor.

{
  "summary": {"products": 120, "available": 104, "outOfStock": 16, "low": 7},
  "products": [
    {"id": "3f1c…", "name": "Milk", "unit": "l", "kind": "simple", "barcode": "626…", "stock": 3, "available": true,
     "status": "low", "lowLevel": 5, "price": 30000, "updatedAt": "2026-11-09T08:10:00.000Z"}
  ],
  "nextCursor": null,
  "revision": 42
}

status is available, low (the shop's own «رو به اتمام» alarm says it is running out; lowLevel is that alarm's amount) or out (sold out).

GET /changes

For a website that keeps its own copy of the products. Send the revision you saw last: GET /changes?since=42.

{"revision": 45, "fullResyncRequired": false, "products": [{"id": "3f1c…", "…": "…"}, {"id": "9a0d…", "removed": true}], "nextCursor": null}
  • products are the full, current products that changed. A removed product comes as {"id", "removed": true}.
  • Save the new revision and use it next time. Nothing changed: products is empty.
  • fullResyncRequired: true: the change log is too old; read GET /products again and start from its revision.
  • More than limit (default 200) changed: call again with cursor=<nextCursor>.

GET /movements

Recent stock changes, newest first. Options: kind=received|sold|used|waste, productId, since (only newer than this time), limit (1–200, default 50). Next page: before and beforeId from next.

{
  "movements": [
    {"id": "…", "productId": "3f1c…", "name": "Milk", "kind": "sold", "correction": false, "quantity": 1, "unit": "l",
     "stockBefore": 8, "stockAfter": 7, "occurredAt": "…", "recordedAt": "…", "saleId": "…", "unitPrice": 30000,
     "origin": {"channel": "website", "method": "api", "by": null, "apiKey": {"id": "…", "name": "shop website"}}}
  ],
  "next": {"before": "2026-11-09T08:00:00.000Z", "beforeId": "…"}
}

GET /sales

Recent sales (receipts), newest first, with their lines. Options: since, limit (1–100, default 20), and before + beforeId from next for the next page.

{"sales": [{"id": "…", "receiptNo": 128, "paymentMethod": "card", "totalToman": 60000, "occurredAt": "…", "note": "Order 1042",
  "cancelled": false, "lines": [{"productId": "3f1c…", "name": "Milk", "unit": "l", "quantity": 2, "unitPrice": 30000, "total": 60000}],
  "origin": {"channel": "website", "method": null, "by": null, "apiKey": {"id": "…", "name": "shop website"}}}], "next": null}

Where an entry came from (origin)

Every movement and sale says where it came from:

origin.channelMeaning
websiteSent through this API with a key (apiKey names the key).
connectorSent by ChatGPT or Claude through the AI connector.
staffTyped in the app by an employee (by is the name).
appTyped in the app by the shop owner.

origin.method is how it was typed: manual (by hand), voice, scan (barcode), image (photo), batch, pdf, excel / csv / json (a file), api, production (a recipe), correction.

POST /products

Create a product. Needs the catalog scope and an Idempotency-Key.

{"name": "Chocolate cake", "sku": "CK-1", "category": "Cakes", "brand": "Home", "unit": "piece", "price": 50000, "description": "Small"}
  • Only name is required. Also allowed: barcode (or sku, the same field), category, brand, size, color, unit (piece, kg, g, l, ml, m …), price, costPrice (needs prices too), description, and your own id (a UUID).
  • A product with the same name already exists: 409 product_exists with its productId. Use PATCH for it instead.
  • Stock is never set here. New stock comes with POST /receipts (goods arrived) or POST /import (a count).
  • Answer 201: {"product": {...}}.

PATCH /products/{id}

Edit a product. Only the fields you send change; null clears an optional field (for example "brand": null). Same fields as POST /products. Optional version: the edit is refused with 409 version_conflict if the product changed since you read it.

{"price": 55000, "category": "Cakes", "version": 3}

Answer 200: {"product": {...}}. The unit of a product that already has stock or history cannot change (409 unit_change_blocked).

POST /sales

Records a sale exactly like the app's basket: it gets a receipt number, stock goes down, made products use up their recipe ingredients, and it counts in sales and profit reports. Stock never goes below zero: if a line asks for more than is on hand the whole sale is refused with 409 insufficient_stock (details: productId, name, stock, unit) and nothing changes.

{
  "lines": [
    {"productId": "3f1c…", "quantity": 2},
    {"barcode": "6260000000017", "quantity": 1, "unitPrice": 28000},
    {"name": "Latte", "quantity": 1}
  ],
  "paymentMethod": "card",
  "note": "Online order 1042",
  "occurredAt": "2026-09-27T10:15:00+03:30"
}
  • Each line names a product by productId, barcode or exact name. An unknown product is 404 product_not_found (line = its position). A name that fits several brands is 409 product_choice_required with candidates.
  • quantity may have up to 3 decimals. unit (optional) converts, for example "g" for a product kept in kg.
  • unitPrice is optional; without it the product's selling price is used.
  • paymentMethod: cash or card (default card). Credit/customer accounts are not available through the API.
  • Answer 201: { "sale": {id, receiptNo, totalToman, lines: [...]}, "products": [...updated products], "revision": … }.

POST /receipts

Records incoming stock like the app's "received" entry. A new name creates the product.

{"lines": [{"productId": "3f1c…", "quantity": 12, "unitCost": 21000, "expiresAt": "2026-12-01"}, {"name": "Bread", "quantity": 20, "unit": "piece"}]}

unitCost (optional) updates the average purchase cost. Answer 201: { "movements": [...], "products": [...], "revision": … }.

PATCH /products/{id}/price

{"price": 32000, "costPrice": 23000, "version": 4}

Send price, costPrice or both (null clears one). version is optional: when sent, the change is refused with 409 version_conflict if the product changed since you read it.

POST /import

Sets each listed product's stock to the counted amount. The difference is saved as a stock reconciliation (it is never counted as sales revenue), and the other columns update the product. Up to 500 rows per request; products not in the file are left alone.

Send one of:

  • JSON: {"rows": [{"name": "Milk", "stock": 12, "barcode": "626…", "category": "Dairy", "brand": "…", "price": 30000, "costPrice": 22000, "unit": "l"}]}
  • CSV with Content-Type: text/csv (first row: نام کالا,موجودی and optionally بارکد,توضیحات,دسته‌بندی,برند,سایز,رنگ,قیمت,قیمت خرید)
  • Excel with Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet (the app's own export, or GET /inventory.xlsx)

With ?dryRun=true the answer lists each row's currentStock, the change and whether it isNew, and nothing is saved. Formulas in files are refused (import_formula).

Safe retries (Idempotency-Key)

POST /sales, POST /receipts, POST /products and POST /import need an Idempotency-Key header: any unique text of 8–100 letters, digits, -, _, . or : (a UUID is ideal). Use a new key for each new sale, and the same key when you retry the same sale after a timeout. A repeat returns the first answer (header Idempotent-Replayed: true) and changes nothing; the same key with a different body is 409 idempotency_conflict. PATCH accepts the header too.

Limits

  • 120 requests per minute per key, and 600 per minute per internet address. Over the limit: 429 rate_limited with a Retry-After header (seconds). Every answer carries X-RateLimit-Limit, X-RateLimit-Remaining and X-RateLimit-Reset.
  • Request body up to 1 MB (6 MB for /import). Up to 60 lines per sale or receipt.

Errors

Errors look like {"error": {"code": "…", "requestId": "…"}} plus details for some codes.

StatusCodeMeaning
400invalid_request, idempotency_key_required, invalid_idempotency_key, invalid_unit, import_invalid, import_limit, import_formulaThe request is not valid.
401api_key_missing, api_key_invalid, api_key_revoked, api_key_expiredNo usable key.
402api_plus_onlyThe shop is not on the «پلاس» (Plus) plan (free, Standard, or Plus ended). Details: plan: "pro", upgrade: true. The key is kept and works again once the shop is on Plus.
403insufficient_scopeThe key does not have the needed scope (required).
403origin_forbiddenA write was sent from a web page; send it from your server.
404not_found, product_not_foundNo such product (or path).
409insufficient_stock, product_choice_required, product_exists, name_taken, idempotency_conflict, version_conflict, unit_change_blocked, name_ambiguous, barcode_conflictThe change conflicts with the current stock or data.
410shop_archivedThe shop was closed.
415unsupported_media_type/import got a file type it does not read.
429rate_limitedToo many requests; wait Retry-After seconds.

Examples

Read stock:

curl -H "Authorization: Bearer $ANBARI_KEY" "https://<your-anbari-address>/api/v1/inventory?available=true"

What is sold out:

curl -H "Authorization: Bearer $ANBARI_KEY" "https://<your-anbari-address>/api/v1/stock?status=out"

Add a product from your website:

curl -X POST "https://<your-anbari-address>/api/v1/products" \
  -H "Authorization: Bearer $ANBARI_KEY" -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"name":"Chocolate cake","sku":"CK-1","category":"Cakes","price":50000}'

Keep your website's copy up to date (server side, every few minutes):

let revision = savedRevision; // from your database
const res = await fetch(`https://<your-anbari-address>/api/v1/changes?since=${revision}`, {
  headers: { Authorization: `Bearer ${process.env.ANBARI_KEY}` }
});
const data = await res.json();
if (data.fullResyncRequired) { /* read GET /products again */ }
else for (const p of data.products) p.removed ? removeProduct(p.id) : saveProduct(p);
saveRevision(data.revision);

Menu website (server side, Node.js 18+):

const res = await fetch('https://<your-anbari-address>/api/v1/inventory?limit=500', {
  headers: { Authorization: `Bearer ${process.env.ANBARI_KEY}` }
});
const { products } = await res.json();
const menu = products.filter(p => p.available).map(p => ({ name: p.name, price: p.price }));

Record a sale:

curl -X POST "https://<your-anbari-address>/api/v1/sales" \
  -H "Authorization: Bearer $ANBARI_KEY" -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"lines":[{"name":"Latte","quantity":2}],"paymentMethod":"card","note":"Order 1042"}'

Send a stock-count Excel file (check first with a dry run):

curl -X POST "https://<your-anbari-address>/api/v1/import?dryRun=true" \
  -H "Authorization: Bearer $ANBARI_KEY" \
  -H "Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet" \
  --data-binary @stock.xlsx

Using an AI assistant (Claude)

The Connections screen has a ready text that explains these endpoints to an assistant. Give the assistant a key with only the scopes it needs (start with inventory:read), ask it to use a dry run before any import, and revoke the key when you are done.
