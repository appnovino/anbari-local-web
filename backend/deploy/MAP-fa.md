# نقشهٔ اتصال و دیپلوی نووینو

## مسیر درخواست

```text
مرورگر → HTTPS / Caddy → Node روی 127.0.0.1:8080 → PostgreSQL روی loopback
                              ├─ کاوه‌نگار → کد ورود و تأیید شماره
                              ├─ زیبال → ساخت و تأیید پرداخت اشتراک
                              └─ OpenAI → پیش‌نویس اقلام فاکتور
مرورگر ← صفحهٔ وضعیت ← بازگشت زیبال ← تأیید سمت سرور
```

- `deploy/Caddyfile` ورودی HTTPS است. وب و API را به یک سرویس می‌فرستد. بررسی سلامت دیتابیس از داخل VPS روی `/healthz` انجام می‌شود.
- `deploy/novino-api.service` سرویس Linux را با کاربر محدود راه می‌اندازد و `/etc/novino/api.env` را می‌خواند. نمونهٔ قابل کپی در `deploy/server.env.example` است.
- `server.mjs` تنظیمات را می‌خواند، مهاجرت‌های دیتابیس را اجرا می‌کند و کار بازیابی پرداخت و پاک‌سازی رکوردهای منقضی را آغاز می‌کند. `database.mjs` اتصال‌ها و تراکنش‌ها را مدیریت می‌کند. ترتیب ساخت جداول در `migrations/` است.
- `web.mjs` فایل‌های مجاز `web/` را ارائه می‌دهد. `web/app.mjs` درخواست‌ها را با نشست کاربر به API همان دامنه می‌فرستد. `api.mjs` مسیرها، نقش فروشگاه و سقف درخواست‌ها را اعمال می‌کند.
- `auth.mjs` نشست و رمز عبور، `shops.mjs` اعضا و کالا و طرف‌حساب، `warehouses.mjs` موجودی انبار، `documents.mjs` اسناد و گزارش، `attachments.mjs` پیوست، `workflows.mjs` چک و یادآور و لیست خرید، و `payroll.mjs` ثبت و اصلاح حقوق را مدیریت می‌کنند.
- `config.mjs` سرویس‌های فعال را می‌سازد. `providers.mjs` ارتباط HTTPS با ارائه‌دهنده‌ها، `sms.mjs` اعتبارسنجی کد، `billing.mjs` سفارش و تمدید اشتراک، و `service-limits.mjs` سهمیه و پاک‌سازی را مدیریت می‌کنند.

## سکرت‌ها و تنظیمات

پنل `/admin` برای حساب‌هایی باز می‌شود که شناسهٔ آن‌ها در جدول `platform_admins` ثبت شده است. مدیریت فروشگاه به‌تنهایی این دسترسی را نمی‌دهد. پنل وضعیت تنظیم سرویس‌ها را نشان می‌دهد. کلیدها در فایل تنظیمات سرور نگه‌داری می‌شوند.

محدودیت پیش‌فرض API برای هر IP برابر ۱۸۰ درخواست خواندن و ۶۰ درخواست تغییر در دقیقه است. می‌توان این سقف‌ها را با `NOVINO_API_READ_LIMIT` و `NOVINO_API_WRITE_LIMIT` تنظیم کرد. API از طریق Caddy آدرس IP را دریافت می‌کند و درخواست بیش از سهمیه را با وضعیت ۴۲۹ برمی‌گرداند.

مقادیر واقعی را در `/etc/novino/api.env` با مالکیت root و مجوز `0600` قرار دهید. برای لوکال از `backend/.env` استفاده کنید. فایل نمونه فقط نام متغیرها و پیش‌فرض‌ها را دارد.

| اتصال | سکرت | تنظیمات |
| --- | --- | --- |
| PostgreSQL | `DATABASE_URL` شامل رمز کاربر دیتابیس | `NOVINO_DB_POOL_MAX` پیش‌فرض ۸ |
| کاوه‌نگار | `KAVENEGAR_API_KEY` و `NOVINO_SMS_SECRET` | `NOVINO_SMS_ENABLED=true`، `KAVENEGAR_OTP_TEMPLATE` تأییدشده و `NOVINO_SMS_DAILY_LIMIT` |
| زیبال | `ZIBAL_MERCHANT` | `NOVINO_ZIBAL_ENABLED=true`، `NOVINO_PUBLIC_ORIGIN=https://novino.app`، `NOVINO_PLAN_AMOUNT_RIAL` و `NOVINO_PLAN_DURATION_DAYS` |
| OpenAI | `OPENAI_API_KEY` | `NOVINO_AI_ENABLED=true`، `OPENAI_MODEL` و سقف‌های `NOVINO_AI_SHOP_DAILY_LIMIT` و `NOVINO_AI_GLOBAL_DAILY_LIMIT` |

برای راز کد پیامکی یک مقدار تصادفی مستقل بسازید. نمونهٔ تولید روی VPS

```bash
openssl rand -hex 32
```

مرورگر فقط توکن نشست خود کاربر را می‌گیرد. کلید ارائه‌دهنده‌ها از Node به سرویس‌های بیرونی ارسال می‌شود. تنظیم زیبال بر حسب **ریال** و ثبت خرید و فروش فروشگاه بر حسب **تومان** است.

## ترتیب نصب و آزمون

برای بستهٔ استقرار، در GitHub Actions اجرای موفق `Novino CI` روی `main` را باز کنید و بستهٔ `novino-vps-<commit>` را بردارید. فایل `novino-vps.tar.gz` را پس از بررسی با `sha256sum -c novino-vps.tar.gz.sha256` باز کنید. CI از دیتابیس آزمایشی جدا استفاده می‌کند. فایل تنظیمات واقعی را روی VPS بسازید.

برای شروع اتصال، آدرس VPS، نام کاربر SSH، پورت SSH و نام توزیع Linux لازم است. احراز هویت SSH با کلید انجام می‌شود. پس از تأیید اتصال و سلامت PostgreSQL، ابتدا وب را بالا می‌آوریم و سپس هر سرویس بیرونی را جداگانه فعال و امتحان می‌کنیم.

1. روی VPS کاربر سرویس `novino` و دیتابیس اختصاصی را بسازید. Node.js 24، PostgreSQL و Caddy را نصب کنید. آدرس Node و PostgreSQL را روی loopback نگه دارید.
2. نسخهٔ پروژه را در `/opt/novino` قرار دهید و `npm ci --omit=dev` را از همان مسیر اجرا کنید. فایل سرویس را در `/etc/systemd/system/novino-api.service` و تنظیمات را در `/etc/novino/api.env` قرار دهید. در استقرار اول سرویس‌های بیرونی را خاموش بگذارید.
3. `systemctl daemon-reload` و `systemctl enable --now novino-api` را اجرا کنید. خروجی `curl --fail http://127.0.0.1:8080/healthz` باید `{"ok":true}` باشد. `journalctl -u novino-api -n 50 --no-pager` برای بررسی خطای راه‌اندازی است.
4. رکورد DNS را به VPS وصل کنید، `Caddyfile` را نصب و با `caddy validate --config /etc/caddy/Caddyfile` بررسی کنید. HTTPS را از بیرون باز کنید. تنظیم نمونه برای ورودی مستقیم Caddy است. برای Cloudflare Proxy، استخراج IP واقعی با پراکسی مورد اعتماد را قبل از عرضه بررسی کنید.
5. در محیط آزمایشی ثبت‌نام را فعال کنید. ایجاد حساب، ساخت فروشگاه، ثبت کالا، خرید، فروش و گزارش را از مرورگر انجام دهید. بازخوانی صفحه باید همان دادهٔ PostgreSQL را نشان دهد.
6. هر سرویس را بعد از قراردادن مقادیرش جداگانه فعال کنید و `systemctl restart novino-api` را اجرا کنید. در کاوه‌نگار دریافت و مصرف یک‌بارهٔ کد را روی شمارهٔ آزمایشی بررسی کنید. در زیبال سفارش، برگشت HTTPS و تمدید یک‌باره را با مرچنت تست بسنجید. در OpenAI یک متن ساختگی بفرستید و بررسی کنید خروجی به‌صورت پیش‌نویس نمایش داده می‌شود.
7. قبل از ورود دادهٔ واقعی، از PostgreSQL پشتیبان بگیرید و بازیابی را روی دیتابیس جدا انجام دهید. برای نسخهٔ بعد ابتدا پشتیبان بگیرید و بعد سرویس را با نسخهٔ جدید اجرا کنید. مهاجرت‌ها هنگام شروع اجرا می‌شوند.

## تشخیص خطا

- اگر `/healthz` روی VPS خطا می‌دهد، اتصال PostgreSQL و گزارش `journalctl` را بررسی کنید. اگر همین مسیر سالم است و دامنه باز نمی‌شود، DNS، HTTPS و Caddy را بررسی کنید.
- اگر صفحهٔ اشتراک «درگاه پرداخت هنوز فعال نیست» نشان می‌دهد، پرچم زیبال و تنظیمات سرویس را بررسی کنید. سفارش معلق را از داخل بخش اشتراک به‌روزرسانی کنید. سفارش `review` بدون شناسهٔ درگاه باید در پنل زیبال تطبیق داده شود.
- اگر فرم پیامکی نمایش داده نمی‌شود، پرچم کاوه‌نگار را بررسی کنید. اگر کد نمی‌رسد، وضعیت الگو، اعتبار پنل و تحویل پیامک را بررسی کنید.
- اگر هوش مصنوعی آماده است ولی خروجی نمی‌دهد، منطقهٔ VPS، دسترسی شبکه، اعتبار حساب و پشتیبانی مدل از خروجی ساختاریافته را بررسی کنید. ایران در فهرست فعلی مناطق پشتیبانی‌شدهٔ OpenAI API نیست. [فهرست مناطق پشتیبانی‌شده](https://help.openai.com/en/articles/5347006-openai-api-supported-countries-and-territories)

## نتیجهٔ بررسی محلی

- پیکربندی Caddy اعتبارسنجی شد. سرویس Node در لوکال به PostgreSQL وصل شد و سلامت دیتابیس را گزارش کرد. پشتیبان آزمایشی PostgreSQL روی دیتابیس جدا بازیابی شد و شمار مهاجرت‌ها، فروشگاه‌ها و ردیف‌های گزارش تطبیق داشت.
- آزمون مرورگر ساخت فروشگاه، کالا، خرید و فروش، موجودی پس از بازخوانی، برگشت جزئی، بارگذاری و دانلود پیوست، حقوق، ورود پیامکی، بازگشت از درگاه و پیش‌نویس هوش مصنوعی را پوشش داد. مسیرهای سه ارائه‌دهنده در مرورگر با پاسخ آزمایشی سنجیده شدند. زیبال با مرچنت تست از شبکهٔ محلی هم شناسهٔ درگاه صادر کرد.
- انتشار روی VPS، گواهی عمومی، پرداخت بانکی کامل، تحویل پیامک واقعی و پاسخ حساب OpenAI پس از فراهم شدن VPS، DNS و کلیدها باید دوباره از همان سرور بررسی شوند.
