# اجرای بک‌اند نووینو

نووینو با Node.js و PostgreSQL اجرا می‌شود. وب‌اپ متصل در مسیر `/` همین سرویس در دسترس است. انتقال داده از نسخهٔ مرورگری قبلی هنوز پیاده نشده است. [نقشهٔ فایل‌ها و ترتیب دیپلوی](deploy/MAP-fa.md)

## اجرای محلی

1. یک دیتابیس خالی PostgreSQL با کاربر اختصاصی بسازید. کاربر به ساخت و تغییر جداول در اسکیمای این دیتابیس نیاز دارد.
2. با Node.js 24 از ریشهٔ مخزن `npm ci` را اجرا کنید.
3. فایل محلی `backend/.env` را با مقادیر محیط خود بسازید. این فایل در Git نادیده گرفته می‌شود.

```dotenv
DATABASE_URL=postgresql://novino:PASSWORD@127.0.0.1:5432/novino
NOVINO_HOST=127.0.0.1
NOVINO_PORT=8080
NOVINO_ALLOW_REGISTRATION=true
NOVINO_TRUST_LOOPBACK_PROXY=false
```

4. `npm run start:backend` را اجرا کنید. مهاجرت‌های دیتابیس به‌ترتیب و در تراکنش اجرا می‌شوند. `GET http://127.0.0.1:8080/healthz` اتصال دیتابیس را بررسی می‌کند.

## قرارداد API

درخواست‌های دارای بدنه از `Content-Type: application/json` استفاده می‌کنند. ثبت‌نام یا ورود یک توکن تصادفی ۳۰روزه می‌دهد. آن را با `Authorization: Bearer <token>` بفرستید. خروج توکن همان دستگاه را باطل می‌کند.

- `POST /v1/auth/register` با `email,name,password` و `POST /v1/auth/login` با `email,password`. حداقل طول رمز ۱۲ نویسه است. `GET /v1/auth/session` و `POST /v1/auth/logout` نشست جاری را مدیریت می‌کنند.
- `GET /v1/shops` فروشگاه‌های حساب را می‌دهد. `POST /v1/shops` با `name` یک فروشگاه و انبار اصلی می‌سازد. شناسهٔ برگشتی را در پیشوند `/v1/shops/<shopId>` برای مسیرهای زیر استفاده کنید.
- `GET/POST /members` و `DELETE /members/<userId>` برای مالک. مالک یک حساب ثبت‌شده را با ایمیل به‌صورت `staff` یا `viewer` اضافه می‌کند.
- `GET/POST /warehouses` و `GET /warehouses/<id>/stock` موجودی به تفکیک انبار. ساخت انبار با مالک است.
- `GET/POST /products` با `name,sku` و `GET/POST /contacts` با `name,phone`. برای ویرایش `PUT /products/<id>` یا `PUT /contacts/<id>` با `version` خوانده‌شده بفرستید.
- `GET/POST /documents`، `GET /documents/<id>` و `GET /products/<id>/movements` برای اسناد و گردش موجودی. `GET /documents?contactId=...` گردش حساب طرف‌حساب را محدود می‌کند.
- `POST /documents/<id>/returns` برای برگشت بخشی یا کل خرید و فروش با `lines` شامل `productId,quantity`. `POST /documents/<id>/reverse` برای ثبت سند معکوس در موارد مجاز.
- `GET/POST /cheques` و `POST /cheques/<id>/settle|bounce|cancel` ثبت چک و وضعیت آن. وصول، سند دریافت یا پرداخت می‌سازد.
- `GET /reports/summary` جمع خرید، فروش، دریافت، پرداخت و هزینه را می‌دهد. `GET /club/<contactId>` امتیاز و سند `redemption` مصرف امتیاز را ثبت می‌کند. مالک می‌تواند نرخ `pointsPerSale` را در `PATCH /v1/shops/<shopId>` تنظیم کند.
- `GET/POST /reminders` و `GET/POST /shopping-list`. یادآور با `title,dueAt` به‌صورت UTC و خرید با `title,quantity` ثبت می‌شود. `PATCH /<collection>/<id>` با `done` وضعیت را به‌روزرسانی می‌کند.
- `POST /documents/<id>/attachments` با `name,mediaType,content` که محتوا Base64 است. سقف هر فایل ۲ مگابایت و نوع مجاز PDF، PNG و JPEG است. دانلود و حذف از `/documents/<id>/attachments/<fileId>` با نشست و مجوز همان فروشگاه انجام می‌شود.
- `GET/POST /payroll/employees`، `GET /payroll/payments` و `POST /payroll/employees/<id>/payments` با `period,earnings,deductions`. `POST /payroll/payments/<id>/reverse` سند اصلاحی می‌سازد. مدیریت حقوق با مالک است. محاسبهٔ مالیات و بیمه جزو این API نیست.
- `GET /sync` شمارهٔ بازبینی فروشگاه را برای بررسی تغییر از دستگاه دیگر می‌دهد. کلاینت پس از تغییر شماره، منابع مورد نیاز را دوباره می‌خواند. صف آفلاین کلاینت و ارتباط بلادرنگ هنوز پیاده نشده‌اند.
- `GET /ai/status` وضعیت فعال‌بودن تنظیمات هوش مصنوعی را گزارش می‌کند. `POST /ai/invoices/parse` با `text` پیش‌نویس اقلام را برمی‌گرداند. کاربر بعد از بررسی می‌تواند جداگانه سند ثبت کند.

نمونهٔ بدنهٔ فروش با مقدار کسری و قیمت واحد به تومان

```json
{
  "kind": "sale",
  "contactId": "<contactId>",
  "warehouseId": "<warehouseId>",
  "lines": [{"productId": "<productId>", "quantity": "1.250", "unitPrice": 10000}]
}
```

مبلغ در ورودی عدد صحیح به تومان است. خروجی مالی و تعداد موجودی رشتهٔ ده‌دهی است. `purchase` و `sale` انبار اصلی را پیش‌فرض می‌گیرند. برای `adjustment` مقدار خط می‌تواند منفی باشد. سند `transfer` با `fromWarehouseId,toWarehouseId,lines` موجودی را بین دو انبار جابه‌جا می‌کند. اسناد `receipt,payment,expense` از `amount` و سند `redemption` از `points` استفاده می‌کند. خرید طرف‌حساب‌دار مانده را کم می‌کند، فروش آن را زیاد می‌کند و دریافت و پرداخت آن را تسویه می‌کنند.

برای ثبت سند، برگشت، چک، پیوست و تسویهٔ حقوق `Idempotency-Key` یکتا بفرستید. ارسال دوبارهٔ همان عملیات و بدنه پاسخ اولیه را می‌دهد. استفادهٔ دوباره از همان کلید با عملیات متفاوت خطای ۴۰۹ می‌دهد. خطاهای API در قالب `{"error":{"code":"..."}}` هستند. فهرست‌های صفحه‌بندی‌شده `limit` تا ۱۰۰ و `offset` می‌گیرند.

## استقرار روی یک VPS

1. Node.js 24، PostgreSQL و Caddy را نصب کنید. یک حساب سیستم `novino` و یک دیتابیس و حساب اختصاصی PostgreSQL بسازید. PostgreSQL و Node روی loopback می‌مانند. دسترسی بیرونی را به HTTPS، HTTP برای صدور گواهی، و SSH مدیریتی محدود کنید.
2. سورس را در `/opt/novino` قرار دهید، `npm ci --omit=dev` را اجرا کنید و سرویس `deploy/novino-api.service` را در `/etc/systemd/system` نصب کنید. مسیر `/usr/bin/node` را روی سرور بررسی کنید. از `deploy/server.env.example` فایل `/etc/novino/api.env` بسازید و مالکیت root و دسترسی ۶۰۰ بدهید. سپس `systemctl daemon-reload` و `systemctl enable --now novino-api` را اجرا کنید و `curl --fail http://127.0.0.1:8080/healthz` را بررسی کنید.
3. پس از تنظیم DNS از `deploy/Caddyfile` استفاده کنید. این نمونه وب و API را در همان دامنه ارائه می‌دهد و برای Caddy در ورودی مستقیم VPS است. اگر Cloudflare Proxy فعال باشد، ابتدا بازه‌های مورد اعتماد Cloudflare و استخراج IP واقعی در Caddy را تنظیم کنید و از TLS معتبر بین Cloudflare و VPS استفاده کنید. با `caddy validate --config /etc/caddy/Caddyfile` پیکربندی را بررسی کنید.
4. برای پایلوت، ثبت‌نام را روی محیط آزمایشی یا دسترسی محدود فعال کنید. مقدار پیش‌فرض `NOVINO_ALLOW_REGISTRATION` خاموش است. قبل از عرضهٔ عمومی مسیر تأیید هویت و بازیابی حساب را مشخص کنید.
5. برای دیتابیس `pg_dump` زمان‌بندی کنید و نسخهٔ رمزگذاری‌شده را خارج از VPS نگه دارید. بازیابی را روی یک دیتابیس جدا تمرین کنید. پیوست‌های فعلی داخل دیتابیس هستند و همراه آن پشتیبان‌گیری می‌شوند.

پیش‌فرض‌ها ۸ اتصال دیتابیس و ۴۸ درخواست هم‌زمان هستند. پردازش هوش مصنوعی تا دو و بارگذاری پیوست تا چهار درخواست هم‌زمان دارد. گزارش خلاصه جمع‌های ثبت‌شده هنگام صدور سند را می‌خواند. بازیابی پرداخت در هر نوبت حداکثر یک تراکنش را برمی‌دارد و وقتی تراکنش موعددار وجود ندارد به زیبال درخواست نمی‌فرستد.

## فعال‌سازی سرویس‌ها

- **کاوه‌نگار.** `NOVINO_SMS_ENABLED=true`، کلید API، نام الگوی تأییدشده و یک راز مستقل حداقل ۳۲ بایتی برای اثبات کد قرار دهید. `POST /v1/auth/sms/link/request` با `phone,password` و نشست فعال شروع می‌شود. `POST /v1/auth/sms/link/confirm` با `challengeId,code` شماره را وصل می‌کند. ورود شمارهٔ وصل‌شده از `/v1/auth/sms/login/request` و `/v1/auth/sms/login/confirm` انجام می‌شود. کد پنج دقیقه اعتبار دارد و یک بار مصرف می‌شود. برای راه‌اندازی یک ارسال و ورود واقعی روی شمارهٔ آزمایشی بررسی کنید. [مستندات کاوه‌نگار](https://kavenegar.com/rest.html)
- **زیبال.** `NOVINO_ZIBAL_ENABLED=true`، مرچنت، دامنهٔ HTTPS، قیمت به **ریال** و مدت طرح را تنظیم کنید. مالک از `POST /billing/checkout` با `Idempotency-Key` لینک درگاه می‌گیرد. وضعیت سفارش را از `GET /billing/payments/<id>` و اعتبار اشتراک را از `GET /billing` می‌خواند. مسیر عمومی `/v1/billing/zibal/callback` ورودی زیبال است و JSON وضعیت را می‌دهد. موفقیت از پاسخ سمت سرور زیبال تأیید می‌شود. وضعیت `review` بدون شناسهٔ درگاه به بررسی در پنل زیبال نیاز دارد. بازپرداخت، اعمال محدودیت امکانات بر اساس طرح، و صفحهٔ بازگشت پرداخت در فرانت‌اند هنوز تعریف نشده‌اند. [مستندات زیبال](https://help.zibal.ir/ipg/)
- **هوش مصنوعی.** `NOVINO_AI_ENABLED=true`، کلید و نام مدل پشتیبان خروجی ساختاریافته را تنظیم کنید. متن فاکتور برای استخراج اقلام به ارائه‌دهنده فرستاده می‌شود. برای آزمون شروع از متن ساختگی استفاده کنید. سقف روزانهٔ هر فروشگاه و کل سامانه جداگانه تنظیم می‌شوند. [مستندات خروجی ساختاریافته](https://platform.openai.com/docs/guides/structured-outputs)

هر سه اتصال در نمونهٔ تنظیمات خاموش‌اند. وضعیت آمادگی API به وجود تنظیمات معتبر اشاره می‌کند. تأیید دسترسی شبکه و کارکرد حساب ارائه‌دهنده روی VPS با آزمون اتصال و حساب واقعی انجام می‌شود.

راهنمای تراکنش و قفل مورد استفاده در این سرویس [node-postgres](https://node-postgres.com/features/transactions) · [PostgreSQL](https://www.postgresql.org/docs/current/explicit-locking.html)

## تست و کارهای باقی‌مانده

`npm test` تست نسخهٔ لوکال را اجرا می‌کند. برای تست API، `NOVINO_TEST_DATABASE_URL` را روی یک دیتابیس اختصاصی آزمایش تنظیم کنید و `npm run test:backend` را اجرا کنید. تست یک اسکیمای تصادفی می‌سازد و همان اسکیما را در پایان پاک می‌کند.

وب‌اپ متصل، مسیرهای ورود و شماره، ساخت فروشگاه، کالا و طرف‌حساب، اصلاح و انتقال موجودی، خرید و فروش و برگشت چندقلمی، دریافت و پرداخت، پیوست، چک، لیست خرید، یادآور، اعضا و حقوق، تنظیم نرخ امتیاز باشگاه، اشتراک و پیش‌نویس فاکتور را دارد. خلاصهٔ مالی بر اساس بازهٔ حداکثر ۳۶۶ روز در منطقهٔ زمانی تهران فیلتر و به CSV صادر می‌شود. بازیابی حساب، اعلان، پشتیبانی، ورود فایل اکسل، گزارش‌های تکمیلی و همگام‌سازی آفلاین هنوز در دامنهٔ کار باقی هستند. حساب‌ها، مانده‌ها و اسناد فعلی برای حسابداری عملیاتی انبار طراحی شده‌اند. حسابداری دوبل، مالیات، قیمت تمام‌شده و سود رسمی به طراحی و آزمون جدا نیاز دارند.
